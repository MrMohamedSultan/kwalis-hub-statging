# Kwalis HUB — Guide for Claude Code

Production accounting platform (film/series/commercial): budgets, top sheet,
payroll, payables, petty cash, treasury, rebate reporting. Bilingual EN/AR with RTL.

## Stack

- **TanStack Start v1** (React 19, SSR, file-based routing) — **not** Next.js, **not** React Router.
- **Vite 7** + `@lovable.dev/vite-tanstack-config`.
- **Tailwind CSS v4** configured through `src/styles.css` (`@theme`) — there is no `tailwind.config.js`.
- **shadcn/ui** components in `src/components/ui`.
- **Supabase** (managed by Lovable Cloud) for DB, auth, storage.
- **i18next** for EN/AR localization.

## Commands

```bash
bun install
bun run dev        # http://localhost:8080
bun run build

```

## Layout

| Path                         | Purpose                                                                      |
| ---------------------------- | ---------------------------------------------------------------------------- |
| `src/routes/`                | File-based routes. `_authenticated/` is behind the auth gate.                |
| `src/routes/api/`            | HTTP endpoints. `api/public/*` bypasses site auth — verify callers yourself. |
| `src/lib/*.functions.ts`     | `createServerFn` RPC callable from the client.                               |
| `src/lib/*.server.ts`        | Server-only helpers; never imported by components.                           |
| `src/lib/mcp/`               | MCP server definition + tools.                                               |
| `src/components/`            | Shared UI.                                                                   |
| `src/integrations/supabase/` | Auto-generated Supabase clients and types.                                   |

## Do not edit

- `src/routeTree.gen.ts` — regenerated by the router plugin.
- `src/integrations/supabase/client.ts`, `client.server.ts`, `auth-middleware.ts`,
  `auth-attacher.ts`, `types.ts` — auto-generated.
- `src/routes/mcp.ts`, `src/routes/[.mcp]/**`,
  `src/routes/[.well-known]/oauth-protected-resource.ts` — generated by the MCP Vite plugin.
  Change `src/lib/mcp/` instead.
- `supabase/config.toml`, `.env` — managed by Lovable.

## Conventions

- Server logic that the app calls itself → `createServerFn` from `@tanstack/react-start`.
  Webhooks / external callers → file routes under `src/routes/api/`.
- Read `process.env.*` **inside** handlers only. Browser config uses `import.meta.env.VITE_*`.
- Every parent/layout route component must render `<Outlet />`.
- Use semantic design tokens from `src/styles.css`. Do not hardcode `text-white`,
  `bg-black`, or `bg-[#hex]` — it breaks theming and dark mode.
- Use logical CSS properties (`ms-`, `me-`, `ps-`, `pe-`) so RTL Arabic renders correctly.
- All user-facing strings go through i18next; add both `en` and `ar` keys.
- Every query must be scoped to the active project / organization — multi-tenant
  isolation is enforced by RLS and mirrored in the client code.

## Database

Schema, migrations, RLS policies and grants are applied through Lovable, not locally.
Every new `public` table needs: `CREATE TABLE` → `GRANT` → `ENABLE ROW LEVEL SECURITY` → policies.
Roles live in a separate `user_roles` table checked via a `SECURITY DEFINER` `has_role()` function —
never store a role on `profiles`.

## Security

**Read `SECURITY.md` before any change that touches RLS, policies, grants, roles,
secrets, `/api/public/*` routes, or `supabaseAdmin`.** It is the authoritative
rule set: table creation order, multi-tenant isolation helpers, forbidden
`USING (true)` policies, server-side zod validation, and the approval workflow
(security changes are proposed as a plan and applied only after user approval).

## Environment

Copy `.env.example` to `.env` and fill the `VITE_SUPABASE_*` values from the project's
backend settings. Server-only secrets (service role key, `LOVABLE_API_KEY`) are held by
Lovable and are not available locally — features depending on them only run in the hosted app.

## Sync

This repo is two-way synced with Lovable. `git pull` before starting work, and push when
done so changes appear in the Lovable editor.
